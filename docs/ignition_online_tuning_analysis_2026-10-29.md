# Онлайн-поиск оптимального УОЗ на m74_9/21129 - анализ (2026-10-29)

Задача: находить оптимальный угол опережения зажигания (УОЗ) во время езды,
не на стенде. Весь текст ниже сверен с фактическим кодом прошивки и текущим
состоянием `firmware/config/boards/m74_9/21129.msq` на 2026-10-29.

## 1. Что такое "оптимальный УОЗ" - физика задачи

Для фиксированной ячейки (обороты, нагрузка/MAP, смесь):

- Кривая момента от УОЗ вогнутая, с **плато** в районе максимума (MBT -
  Maximum Brake Torque). Чувствительность у плато ~0.5-1.5% момента на 1°,
  т.е. оценка argmax плохо обусловлена: +-2° вокруг MBT меняют момент
  меньше, чем шум любого измерения "на ходу".
- Ограничение по детонации **резкое** (порог по звуку/вибрации, за ним -
  риск повреждения). При высокой нагрузке предел детонации лежит РАНЬШЕ
  MBT -> оптимум на дороге = граница детонации минус запас.
- Два режима, и методы в них разные:
  - нагрузка низкая/средняя: детонации нет, оптимум = плато (метод B, сигнал
    слабый);
  - нагрузка высокая: оптимум = граница детонации (метод A, сигнал чёткий).
- Смесь (AFR) сдвигает границу: беднее = граница ближе. Без измеренной
  лямбды поиск границы опасен (известное состояние m74_9: узкополосный
  датчик смонтирован 1:1, но кривая не перекалибрована - потолок 14.0 AFR,
  опорных данных о текущей смеси нет).

Важный факт для 21129: базовая карта УОЗ уже **не с нуля** - это конвертация
заводских карт ME17 (.clb "Базовый УОЗ режим ЧН/ПМ") в 30x16-таблицу по MAP
(`ignitionRpmBins` 600..6250, 16 рядов MAP). Заводская карта для этого мотора
и этой прошивки сбалансирована (MBT/пограничная с запасом). Поэтому
онлайн-поиск - это **трим +-2..4° поверх заводской карты**, а не калибровка с
нуля; и первая гипотеза для любой аномалии - смещение по оси MAP из
mg->кПа-конверсии, а не ошибка самого УОЗ.

## 2. Что уже есть в прошивке (проверено по коду)

### 2.1 Канал детонации - ПОЛНЫЙ, но не настроен и не валидирован на машине

Цепочка целиком существует:

- Железо: разъём AA3 (датчик детонации +, AB3 - земля) -> операционный
  усилитель SGM321/LM321 (AC-связь) -> PA0 = ADC1 IN0 (покой ~1.76 V).
  Проверено на стенде (`firmware/config/boards/m74_9/knock_config.h`,
  диагностики knocktest/knockpin).
- ALU-сбор: окно от угла после искры (knockDetectionWindowStart=20°,
  knockSamplingDuration=15° образцов), DMA-циклический буфер, ~160 кГц
  (`KNOCK_SAMPLE_RATE = 5940000/(24+13)`; ADC1 делится с медленным опросом -
  цепочка медленного опроса прерывается на время окна и возобновляется).
- DSP: биквад-полосовик с центральной частотой **7000 Гц** в 21129.msq
  (`knockFrequency=7000`), что совпадает с формулой первого тона для диаметра
  82 мм: `2 * bore2frequency(0.082) = 2 * 900/(pi*b/2) ~= 6988 Гц`. RMS в
  относительных dB (10*log10 среднего квадрата отфильтрованных отсчётов -
  шкала относительная, не физические dB).
- Логика: поцилиндровые пиковые детекторы (`m_knockCyl[c]`, hold 50 мс),
  общий `m_knockLevel`, порог = `knockBaseNoise` по `knockNoiseRpmBins`,
  усиления `knockGains[c]` (rpm x load), контроллер ретарда
  (`knockRetardAggression` - % расстояния до -20° за событие,
  `knockRetardReapplyRate` в °/с, `maxKnockRetardTable` rpm x load),
  топливный трим при детонации (`knockFuelTrim`).

Состояние в 21129.msq - канал ЭКВИВАЛЕНТНО ВЫКЛЮЧЕН:
`knockRetardAggression=0` (нет ни одного градуса ретарда), `knockBaseNoise`
= -20 dB по всей оси оборотов (порог никогда не пересекается),
`knockGains=0`. То есть уровни считаются и логируются (MLG-каналы
`Knock: Cyl`, `m_knockLevel`), но ни на что не влияют и на реальной
детонации не проверялись.

### 2.2 Момент (виртуальный стенд) - есть

`EFI_DYNO_VIEW` (`firmware/controllers/algo/dynoview.cpp`): ускорение колёс из
`VehicleSpeed` (на m74_9 принимается Largus CAN 0x29A - уже слит),
масса 1000+95 кг, аэродинамическое сопротивление, SAE-коррекция -> каналы
`hp` / `torque` (обновляются в 20 Гц slow-цикле, доступны как
`getOutput("hp")`/`getOutput("torque")` из Lua). В msq заданы колесо
235/40-18, главная пара 4.2, но `dynoCarGearRatio=1.0` - для корректных Nm
надо проставить передачу, на которой едем; форма кривой и её максимум от
этого не зависят (постоянный множитель).

### 2.3 Точка приложения трима - есть штатная

Порядок коррекций (проверено в `engine2.cpp` L223-285 и
`ignition_state.cpp`):

```
timingAdvance[ц] = базовоЈ(карта + бленды + idle-таблица + idle timing PID + IAT/CLT)
                   [getWrappedAdvance] * luaTimingMult + luaTimingAdd
                   - knockRetard - limpRetard
                   + getCylinderIgnitionTrim(ц, rpm, load)
                   + sparkHardwareLatency
```

Существенно: **Lua-аддер применяется ДО вычитания knock-ретарда** - то есть
любой онлайн-трим остаётся под защитой контроллера детонации (он отнимет своё
поверх). И есть **поцилиндровый хук** `custom_board_getCylinderIgnitionTrim`
(`ignition_state.cpp` L292, `board_overrides.h`) - штатная точка для
перманентного поцилиндрового трима из C++.

### 2.4 Lua - прототип целиком без перепрошивки

Доступно: `getSensor("Rpm"/"Map"/"Tps1"/"VehicleSpeed")`,
`getOutput("m_knockLevel"/"Knock: Cyl"/"m_knockCount"/"hp"/"torque")`
(под `EFI_TUNER_STUDIO && EFI_PROD_CODE` - m74_9 проходит),
`setTimingAdd(deg)`/`setTimingMult`, `Timer.new()`, `table3d`, таблицы в RAM
Lua. Доп. плюс m74_9: автономные скрипты можно возить на SD и править на ходу
без прошивки.

### 2.5 Чего НЕТ (необратимо без железа)

- Ion sensing / давление в цилиндре (метод C - фазировка сгорания CA50):
  в rusEFI остался только путь CDM-модуля (`cdmInputPin` ->
  `engine->knockLogic(...)`, Saab Trionic), на борту m74_9 нет ни ion-цепи,
  ни датчика давления - метод заводских ЭБУ исключён.
- Широкополосная лямбда: есть только узкополосный AK3 (1:1, кривая не
  перекалибрована) - опора на него в поиске невозможна.

## 3. Методы

### A. Поиск границы детонации (knock-limited / borderline) - ОСНОВНОЙ для высокой нагрузки

Алгоритм (классика автокалибровки):

```
если ячейка (rpm, MAP) стабильна >= 2 с и двигатель прогрет и MAP > порог:
    если событий детонации нет за последние N с: trim += +0.5..1° (лимит макс.)
    иначе (событие): trim -= 2..3°, пометить ячейку "найдена", не возвращаться
финал ячейки = последний тихий угол - запас 2° (разброс топлива)
```

Плюсы: сигнал чёткий (событие/нет), сходимость минутная, результат = заводская
стратегия. Минусы и риски:

- Детонация - риск повреждения. Страховки обязательны: сначала включить
  штатный контроллер (aggression >= 40-50%, max retard 8-10°, reapply 3°/с) и
  вести поиск только при обогащении (по тюну WOT lambda 0.837). Контроллер
  даёт ретард по формуле "расстояние до -20° x aggression" за каждое событие -
  это и есть сеть безопасности поверх поиска.
- Порог детонации валиден только после калибровки шума: `knockBaseNoise` по
  оборотам (сейчас -20 везде). До этого метод A НЕ РАБОТАЕТ - канал не
  отличает стук от фона.
- На низкой/средней нагрузке детонации физически нет - метод A там ничего не
  находит (и не должен).

### B. Поиск MBT по моменту (градиент / свип) - для средних нагрузок

Свип УОЗ при фикс. ячейке, фикс. передаче, фикс. педали, ровной дороге:

```
для theta в {база-3°, база-1.5°, база, база+1.5°, база+3°}:
    выдержать 3-5 с, усреднить torque (или производную rpm)
подогнать параболу -> argmax; финал = argmax - 0..0.5°
```

Проблемы: чувствительность у плато мала (шум дороги/ветра одного порядка -
оценка argmax имеет точность +-1.5..2° в лучшем случае), необходимы секунды
на точку, смесь должна быть заморожена (STFT/LTFT не трогать во время свипа:
LTFT-запись это MFS-столл и сдвиг смеси), температура впуска медленно ползёт
(коррекция IAT меняет УОЗ => интерпретировать сдвиг). Вывод: свип оправдан
как 1D-проверка отдельных ячеек карты, а не как массовый 2D-поиск.

### C. Фазировка сгорания (CA50/ion/pressure)

Эталонный заводской метод (замкнутая петля по сгоранию), но на m74_9
отсутствует железо (см. 2.5). Решение по фазе сгорания на дороге возможно
только через давление (врезаемой датчик) или ion-sense - за рамками.

## 4. Честная достижимость на дороге

| Регион карты | Что даёт онлайн | Точность |
| --- | --- | --- |
| MAP > ~65 кПа | граница детонации - 2° (метод A, после калибровки шума) | +-1° |
| MAP 40..65 кПа | подтверждение/подстройка плато (метод B) | +-2° |
| MAP < 40 кПа / idle | поиск бессмыслен или вреден (плато широчайшее; в idle - конфликт с idleTimingPid и отдельной idle-таблицей; трим gate обязателен) | - |

Итог: онлайн-поиск на этом моторе сводится к (1) валидации и калибровке
канала детонации, (2) охоте за границей в высоконагруженных ячейках, (3)
спорадической проверке плато свипами. Всё остальное - заводская карта как
база. Это же и самый безопасный порядок.

## 5. Рекомендуемая последовательность работ

1. **Валидация канала детонации** (безопасно, на текущей карте, детонации
   быть не должно): несколько поездок с логом `m_knockLevel`/`Knock: Cyl` по
   rpm/нагрузке; при разгоне высоконагруженный диапазон; после - карта шума
   = медиана по rpm (или спектрограмма: `enableKnockSpectrogram=yes`). Так же
   - проверка, что у стука (если встретим) уровень отрывается от фона на
   >3-5 dB. Тест канала: knocktest/knockpin.
2. **Страховка**: вписать `knockBaseNoise` (фон + запас 4-6 dB),
   `knockRetardAggression=40-50`, `maxKnockRetardTable` 8-10° на высокой
   нагрузке, `knockRetardReapplyRate=3`. Проверить на машине, что ретард
   появляется только при реальных событиях, не фонит.
3. **1D-контроль карты**: 2-3 точки rpm на фix. MAP (и наоборот) свипами по
   моменту - оценить сдвиг, а не править вслепую.
4. **Высоконагруженные ячейки**: метод A (шаг +0.5°, запас 2°, с обязательной
   страховкой п.2 и обогащением).
5. **Персистенс**: результаты в msq руками (или трим-таблица в C++ модуле,
   см. 6.2). Никаких TS-burn в движении (MFS-столлы и сдвиг фаз записи).

Чего НЕ делать: поиск при выключенной страховке, поиск при неоткалиброванной
лямбде, варьирование УОЗ в idle (там уже настроен torque-reserve контур
timing PID - это другой регулятор и другая таблица), поиск при нестабильном
триггере.

## 6. Варианты реализации

### 6.1 Lua-прототип (дни работы, без прошивки)

Скелет (rate ~2 Гц через `Timer.new()`, НЕ onTick; все имена хуков реальные):

```lua
-- cell offsets живут только в RAM Lua: это сессионный инструмент,
-- результаты печатаются и вносятся в msq вручную
local offs = {}          -- key = rpm.."_"..map
local stepDeg = 0.5
local lastKnockCount = 0

local searchTimer = Timer.new()
function onTick()          -- gate: не idle, прогретый мотор, MAP в полосе
    if getSensor("Tps1") < 3 then setTimingAdd(0) return end
    local r = getSensor("Rpm"); local m = getSensor("Map")
    if r < 900 or m < 55 or not searchTimer:getElapsedSeconds() > 2 then return end
    searchTimer:reset()
    local key = math.floor(r/250) .."_".. math.floor(m/5)
    offs[key] = offs[key] or 0
    local k = getOutput("m_knockCount")
    if k > lastKnockCount then
        lastKnockCount = k
        offs[key] = offs[key] - 2.0        -- событие: назад и больше не вперёд
        keyDone[key] = true
    elseif not keyDone[key] and offs[key] < 4 then
        offs[key] = offs[key] + stepDeg   -- тихо: +0.5° за 2 с
    end
    setTimingAdd(offs[key])
end
```

Ограничения прототипа: аддер ГЛОБАЛЬНЫЙ (не поцилиндровый), 100 ms-задержки
нет (трим применяется с 200 Гц цикла - достаточно), таблица RAM-только
(потеря при сбросе - приемлемо: результат в консоль и в msq), порог детонации
должен быть уже откалиброван (п.2). Событие детонации лучше читать как
дифференциал `m_knockCount` (или `Knock: Detected recently`), а не уровень.

### 6.2 C++ модуль (production, после валидации канала)

- Новый `EngineModule` (паттерн `type_list` в `engine.h`, правила
  `[tag:disable_engine_module]`) или проще - доска m74_9: функция в
  `board_configuration.cpp`, регистрируемая в
  `custom_board_getCylinderIgnitionTrim` (уже есть хук, сигнатура
  `(cyl, rpm, ignitionLoad) -> angle`).
- Своя трим-таблица rpm x load (или MFS-запись), логика A/B как выше,
  события из `KnockController::hasKnockRecently`/`getKnockCount()`, gate по
  `IdleController::isIdlingOrTaper()` (и/или `idle`-канал), порог нагрузки,
  полное отключение при limp/pasilaunch. Персистенс по остановке двигателя
  через debounce-гейт записи (штатный паттерн `custom_board_allowFlashNow`).

Затраты C++ пути: таблица/страница конфигурации (или MFS-запись) + тесты;
выигрыш - поцилиндровость, персистенс, защита от гонок с ретардом.

### 6.3 Порядок применения итогового трима (важно)

Трим добавляется ПОСЛЕ knock-ретарда в `engine2.cpp` L278-282 - то есть
ретард при событии садится на (база+трим), как и нужно. Итоговая картинка:
найденные офсеты переносятся из прототипа/модуля в `ignitionTable` msq один
раз после сессии - и остаются частью базовой карты (тогда таблица снова =
заводская + найденное, и поиск можно повторить на новом уровне).

## 7. Риски и открытые вопросы

- Канал детонации ни разу не видел реального стука: отрыв порога от фона
  (dB-шкала относительная) - первая проверка перед любым поиском.
- Реальный диапазон "knock-limited" для 21129 не измерен: начинать поиск с
  MAP > 65 кПа и шага +0.5°.
- Трим при неоткалиброванной лямбде (узкополосная кривая с потолком 14.0) -
  стоп-фактор для высоконагруженного поиска.
- Влияние idle/TPS на границу (TPS taper с пинов 1.24% в покое) - gate
  прототипа по Tps1 >= 3 обязателен.
- Лог для оценки: m_knockLevel, knockCyl, hp/torque, Rpm, Map, Tps1 +
  timingAdvance[0] (MLG), либо вывод прототипа в консоль.
